## Findings

Disposition: fix now / defer / accept. Source references are files in the repository or commits.

### Behavior check (screenshots of home, chapter, topic, search, map, nothing-found, in English, Urdu and at 360 px)

- **B1. The Urdu learning map drew every topic name and row label outside its box.** `src/features/map/MapGraph.tsx` anchored right-to-left text with `textAnchor="end"`; in SVG `text-anchor` start and end follow the text direction, so the text ran past the box and the picture looked empty. Found only by looking: the unit test checked that `direction="rtl"` was present and the e2e check passed for an `<a>` with a rect. *Fixed in `d3a069d`*, with an e2e test that measures every node's and row's text against its box in both languages. Disposition: **fixed**.
- **B2. Urdu headings and card titles overlapped the line below.** Tailwind's `text-*` classes set their own `line-height` and override the Urdu line height the page sets on `body` (`src/styles/fonts.css`; `.text-4xl{line-height:var(--tw-leading,...)}` in the built CSS). Seen on the Urdu home page (`home-ur-phone` screenshot) and affecting every Urdu page that uses those classes, including the Epic 2 topic page. *Fixed in `d3a069d`* with a rule giving headings and the large text classes the Urdu heading line height, and a computed-style e2e test. Disposition: **fixed**.
- **B3. Everything else looked right:** home, chapter, search, topic (prerequisites box), English map, the nothing-found page, and the phone layout of home had no clipping or overlap. The English map's titles are cut at 22 characters (the list has full titles). Disposition: accept.

- **A1. Lint's layer rules do not see either. Disposition: **fix** (action item 31).

The pattern "static page, shared screen component, harness page" is repeated three times (home, search, map) on purpose and documented in `docs/coding-standard.md`. Disposition: **fix** the first two (action item 32), accept the harness pattern.

- **A4. Pattern divergence.** Links: `TopicLinks` now uses `Link` like the rest; the map's SVG and list links use plain `<a>` (SVG links in a hidden picture; list links accepted as full-page navigation). Accept.

## Acceptance verdict

**Accepted with open items** (criteria declared: the story acceptance criteria in `_bmad-output/planning-artifacts/epics.md`). A human decision: Fahd chose this verdict and chose to mark the stories done.

Evidence: every acceptance criterion of Stories 5.1 to 5.5 is met in the built behavior and pinned by tests: published-only lists, counts and links (FR-1.9), the home page and the friendly not-found page (FR-1.1, 1.10), search with Urdu folding and filters under a second for 600 topics (FR-1.4, 1.5, NFR-1.5), direct links in the link's language with prerequisites that never lock (FR-1.6, 1.8), Share (FR-1.11) and the learning map with a full list alternative (FR-1.7). Verification: `npm run check` green (1,822 unit tests, including the migrations on PGlite with Supabase's roles), Playwright 674 tests on Chrome 111 and Edge 111, and a screenshot behavior check that found and fixed two real Urdu defects. Open items that keep it from plain "accepted": catalog and page revalidation and the written `catalog.json` (Story 7.3), the run on a live Supabase project, the static-route gap, the shared-code and cycle cleanup, and the Urdu map polish.

## Open questions

- Should the learning map keep Urdu text at a fixed 13 px inside a 176 px node (it fits for the fixtures, not measured on long titles)? A human reading the Urdu map would settle it (action item 40 and the deferred entry).
- Is it right that visitor pages stay static and refresh only through the publish saga, so an unpublished topic stays visible on the home and tree pages until Story 7.3's revalidation runs? The architecture says yes, with a 60-second target; nothing here can show it yet.
